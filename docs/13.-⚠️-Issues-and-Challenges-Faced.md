**3. ML Model Issues:**

*  GPU-Related Error in YOLOv8:

RuntimeError: CUDA out of memory

This error occurred when the model tried to allocate more GPU memory than was available. It is commonly triggered by:

•	Large batch sizes or input image dimensions,

•	High model complexity,

•	Insufficient GPU memory (e.g., <8GB VRAM).

•	RuntimeError: CUDA out of memory

→ Model, batch size, or image size too large for available GPU memory.

•	ZeroDivisionError: division by zero

→ Usually due to empty validation set or no detections.

•	FileNotFoundError

→ Image or label paths missing or misconfigured in data.yaml.

•	Unsupported Export Formats:

Some target platforms did not support the exported model formats directly, leading to conversion failures or compatibility issues.

•	Quantization Limitations:

Converting the model to lower-precision formats (e.g., for TensorRT or Edge TPU) introduced quantization challenges, which affected model accuracy or caused export failures.

•	Hardware Compatibility Issues:
Inference on certain edge devices failed due to precision mismatches (e.g., float32 vs. int8), requiring additional post-processing or model optimization steps.

•	Incompatible Output Tensor Format for Coral Edge TPU
                 During deployment of the YOLOv8 model to the Coral Edge TPU, a compatibility issue was encountered. The exported    TensorFlow Lite (TFLite) model produced a single raw output tensor, which does not meet the Coral TPU’s requirement for object detection. Specifically, the Coral Edge TPU expects models to output four distinct tensors:

•	boxes – bounding box coordinates

•	classes – detected class indices

•	scores – confidence scores

•	num_detections – total number of valid detections

Proposed Solutions:

1.	Re-export the model with NMS = True This integrates the post-processing step into the model itself, producing the required four-output tensor structure compatible with Coral TPU.

2.	Apply manual NMS in Python after inference if re-exporting isn’t possible.If re-exporting is not feasible, apply manual Non-Max Suppression (NMS) in the host system after inference. This involves parsing the raw output tensor and filtering overlapping bounding boxes using Intersection-over-Union (IoU) metrics in Python.


**4. Networking and Cluster Setup:**

* How to use Laptop as a Router?

In order connect all the Raspberry Pi Machines using Network Switch we need to have a router to act as a Network Provider. Incase of no router availability, it is possible to use the Laptop as a router.

Here we're using Windows-11 based Laptop as a Router.

Step-1: Press `Windows + R`

Step-2: Run `ncpa.cpl`

Step-3: Make sure there are two adapter(s), Ethernet and Wifi.

Step-4: Optional Reset all the network configuration and restart system.

Step-5: Right click on the Wifi Adapter and open the Properties.

Step-6: In the sharing tab, just enable the option:
Allow other network users to connect through this computer's network connection

Step-7: Press Ok and save the settings.

Now, Wifi-adapter will automatically assign the IP address like `192.168.137.1` with subnet mask `255.255.255.0`



* Node joining issues:
   DNS Issue(s) in Nodes
k3s cluster's master-node was not able to pull any images from the docker-hub due to DNS issues because on all nodes DNS was linked to `system-d-resolved` which was not allowing the nodes to access the hosts outside the cluster.

Steps for the Solution:

Run command: `sudo ln -sf /run/systemd/resolve/resolv.conf /etc/resolv.conf`

Then run: `sudo cat /etc/resolv.conf`

Add in the file:
`$ nameserver 8.8.8.8`

`$ nameserver 1.1.1.1`

`$ search .`

Save the file and restart the deployment.

 solution:
MinIO is not by-default configured to give the Public-URL to access the image uploaded to the Bucket.

`minioClient.setBucketPolicy(env.MINIO_BUCKET, JSON.stringify(policy), function (err) {
 if (err) return console.log("Error setting policy:", err);
console.log("Public read policy applied.");
});`
